# 태스크 워커 프롬프트 로그 비효율·잘못된 탐색 패턴 (2026-05-12)

## 요약

Claude Code 기반 태스크 워커 실행 시 `.orchestration/output/prompt-logs/.../*.jsonl`에 쌓이는 스트리밍 로그를 보면, **비용·턴이 불필요하게 커지는 패턴**과 **`Glob` 등으로 잘못된 경로를 먼저 찍는 패턴**이 반복된다. 원인은 “태스크 문구가 너무 넓다” 단일 요인이 아니라, **태스크의 구현 수단 미명시**, **레포에 기대 파일이 없음**, **`worker-task.md`의 최소 탐색 규칙과 모델 실제 행동의 괴리**가 겹친 경우가 많다.

참고로 본 문서는 **TASK-370** 워커 런 로그(예: `.../tasks/TASK-370/work/runs/2026-05-12T06-04-39-553Z.jsonl`) 관찰을 바탕으로 정리했다.

## 관측된 비효율

### 1. 스트리밍 로그 자체의 부피

- `stream_event` + `content_block_delta`가 **작은 JSON 조각**으로 수백 줄씩 쌓인다.
- `Write` 도구는 **파일 전체가 `input_json_delta`로 쪼개져** 같은 내용이 매우 길게 기록된다.

이는 반드시 “에이전트가 나쁘다”는 뜻이 아니라, **로그 포맷이 원본 스트림을 그대로 보존**하기 때문이다. 다만 디스크·리뷰 비용은 커진다.

### 2. 잘못되거나 과도한 `Glob` 패턴

로그에서 보이는 전형:

- `packages/dashboard/src/components/ui/tooltip*` → **No files found** (프로젝트에 해당 컴포넌트가 없을 수 있음).
- 이어서 `packages/dashboard/src/components/ui/*.tsx` → **스토리 등 다수 파일**이 한꺼번에 반환되어 컨텍스트만 비대해짐.
- `packages/dashboard/src/styles/**/*.css` → **No files found** (레포마다 글로벌 CSS 경로가 다름).

`packages/dashboard/template/prompt/worker-task.md`에는 scope 위주·최소 탐색이 있으나, 모델이 **선입견(shadcn 경로 등)** 으로 넓은 탐색을 먼저 하는 경우가 있다.

### 3. 불필요한 도구 라운드트립

- 이미 세션에 노출된 도구인데 **`ToolSearch`로 `TodoWrite`를 조회**하는 등, **추가 턴**만 늘어나는 호출.

### 4. `Write`로 전체 덮어쓰기

작은 변경에도 **전체 파일 `Write`**를 쓰면 **출력 토큰·로그 줄 수**가 커진다. 가능하면 **`Edit`/패치**가 더 가벼운 경우가 많다.

### 5. `TodoWrite` 타이밍

작업이 끝난 뒤에야 모든 항목을 `completed`로 기록하면, **진행 추적용 도구로서의 이득이 거의 없고** 턴만 추가될 수 있다.

### 6. 지저분한 워킹 트리

`git status`에 스코프 밖 변경·미추적 파일이 많으면, 에이전트가 **확인용 `Bash`를 반복**하거나 판단을 보수적으로 가져 **턴이 늘어날** 여지가 있다.

### 7. 높은 모델·턴·출력 토큰

동일 기능이라도 **Opus + 다수 턴 + 큰 출력**이면 비용이 크게 나올 수 있다. 로그 메타데이터상 **수백 초·수만 출력 토큰·달러 단위 비용**까지 올라간 사례가 있다.

### 8. “Agent team” 지시와 실제 실행

프롬프트에 병렬 역할 분담이 있어도, 실제로는 **단일 에이전트가 도구를 순차 호출**하는 형태로 끝나는 경우가 있다. 규칙만 있고 구조가 맞지 않으면 **비용 대비 조직화 이득이 없을** 수 있다.

## 왜 잘못된 패턴을 검색하는가 (태스크가 “너무 넓어서”만은 아님)

| 요인 | 설명 |
|------|------|
| 태스크가 UX·기능만 명시 | “툴팁/접근성”만 있고 **구현 수단·파일 경로**가 없으면 모델이 `Glob`로 추측한다. |
| 레포에 기대 파일 부재 | `tooltip` 컴포넌트가 없으면 첫 `Glob`는 실패하고, 다음 추측으로 범위가 넓어질 수 있다. |
| 레포 구조 가정 오류 | `styles/**/*.css` 같은 **일반화된 경로**는 프로젝트마다 틀리기 쉽다. |
| 규칙 준수의 한계 | `worker-task.md`에 “최소 탐색”이 있어도, 모델이 **항상 scope 파일을 먼저 `Read`**하지는 않는다. |

## 완화 방안 (태스크 작성)

- **허용 수단을 한 줄로 고정**: 예) “네이티브 `title`/`aria-label`만 사용, 새 Tooltip 패키지·새 UI 파일 추가 금지”.
- **수정 대상 파일을 나열**하거나, “다음 파일만 변경”을 명시.
- **금지 행동**을 짧게: 예) “불필요한 `Glob`/`find` 금지, scope 파일을 먼저 연다”.
- 스코프 밖 작업이 필요하면 **별도 태스크**로 분리.

## 완화 방안 (실행 환경)

- 워커 실행 전 **워킹 트리 정리**(스코프와 무관한 로컬 변경 최소화).
- 비용이 민감하면 **모델/턴 상한** 정책을 별도로 검토.
